### How to work in this crate (read this first)

Layout: `apps/desktop/src-tauri` is the Cargo workspace;
`crates/openfinance-core` holds all backend code. Run cargo from `apps/desktop/src-tauri`.

**Gates** (all must pass; paste the output in your report):
```
cd apps/desktop/src-tauri
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
node crates/openfinance-core/parity/run.mjs        # from anywhere in the worktree
```
The Tauri app crate's build script needs the sidecar files to exist. In a fresh
worktree create git-ignored placeholders once:
`mkdir -p binaries/server-bundle && touch binaries/server-aarch64-apple-darwin binaries/server-bundle/index.js && chmod +x binaries/server-aarch64-apple-darwin`.

**State and DB.** Handlers take `State(state): State<AppState>`.
- `state.db(|conn| { ... Ok(value) }).await` runs a closure with the single
  `rusqlite::Connection` on the blocking pool (autocommit). The closure must be
  `Send + 'static`, so move owned inputs in.
- `state.transaction(|conn| ...).await` is `runTransaction`: BEGIN/COMMIT,
  ROLLBACK on `Err`. Calls are serialised. Inside a closure, call
  `db::run_transaction(conn, |conn| ...)` to get the same semantics; when a
  transaction is already open it joins it (Node's `depth > 0` path).
- Write services as plain functions taking `&Connection` (easy to compose in
  one transaction and to unit-test on `Connection::open_in_memory()` +
  `db::bootstrap::bootstrap_schema`). Only code that awaits network I/O takes `&AppState`.
- Never hold the connection across an `.await`; split DB work and network work
  like `services/exchange_rate.rs::refresh_from_web`.
- `state.config()` replaces `process.env` (`desktop`, `no_network`, `data_dir`, …);
  `state.file_crypto()` is `getFileEncryptionKey()` + the desktop flag for OFE1;
  `state.http()` is the shared `reqwest` client (respect `config().no_network`).

**IDs, time, JSON.** `ids::nanoid()` (npm alphabet/length), `js::now_iso()`
(`new Date().toISOString()`), `js::js_trim`. `json::from_sql(row.get_ref(i)?)`
turns a column into the JSON value drizzle/better-sqlite3 would produce
(INTEGER/REAL → number, TEXT → string). Booleans stored as integers must be
converted to `true/false` explicitly where drizzle uses `mode: "boolean"`.
`json::parse_body` / `json::body_or_empty_object` replicate `c.req.json()` and
`.catch(() => ({}))`; take the body as `axum::body::Bytes`, not `Json<T>`, so
parse failures map to Node's status/body rather than axum's rejection.
`serde_json` has `preserve_order`, so `json!`/`Map` keep insertion order like JS.
f64 `1.0` serialises as `1.0` (Node: `1`); both parse to the same number, so the
harness treats them as equal.

**Errors.** Return `ApiResult<T>`. In services: `ApiError::service(404, "Account not found")`
for Node's `Object.assign(new Error(msg), { status })`, `ApiError::plain(msg)` for a bare
`throw new Error`, and `?` on `rusqlite::Error` (→ 500). In routes, mirror that
file's `handleError` with `.map_err(|e| e.handled(&[404]))`: listed statuses pass
through with their message, everything else becomes a logged
`500 {"error":"Internal server error"}`. Use `ApiError::validation(details)` for
`{"error":"Validation failed","details":…}` (the harness ignores `details`),
`ApiError::bad_request`, `ApiError::not_found`, or `ApiError::body(status, json)`
for any other shape. No `unwrap`/`expect`/`panic!` on request paths.

**Adding routes.** Edit only your `http/routes/<domain>.rs` (its `router()` is
already mounted at the Node prefix) and `services/<domain>.rs`. Paths inside
`router()` are relative: `.route("/accounts/{id}", get(...))` (axum 0.8 uses
`{id}`). Unknown paths and wrong methods already return Hono's
`404 text/plain "404 Not Found"`; a trailing slash is a 404 like Hono. CORS, the
origin guard, logging and the unlimited body size are applied globally.

**Parity harness** (`crates/openfinance-core/parity`):
`node apps/desktop/src-tauri/crates/openfinance-core/parity/run.mjs [--no-build] [--keep] [--verbose] [name-filter ...]`.
It builds `openfinance-server`, seeds a temp DB by `POST /api/backup/import`
(a ZIP of `sample-data.json`) on Node, restarts Node once so startup jobs settle,
then for each scenario copies the seed twice, starts Node and Rust with
`OPENFINANCE_DESKTOP=true OPENFINANCE_NO_NETWORK=1 OLLAMA_URL=http://127.0.0.1:9`,
sends every step to both and compares status, selected headers
(`content-type`, `content-disposition`, `vary`, `access-control-allow-*`) and
body. Exit code 1 on any diff. If `apps/server/node_modules` or
`packages/shared/node_modules` is missing in your worktree it symlinks them from
the main checkout.

Scenario file (`parity/scenarios/<domain>[-topic].json`, one fresh DB per file,
steps run in order):
```json
{
  "description": "what this covers",
  "steps": [
    { "name": "create", "method": "POST", "path": "/api/budget/accounts",
      "json": { "name": "X", "type": "checking" }, "capture": { "acc": "account.id" } },
    { "name": "read back", "method": "GET", "path": "/api/budget/accounts/{{acc}}",
      "headers": { "Origin": "tauri://localhost" } }
  ]
}
```
Bodies: `json` (sets `Content-Type: application/json`), `body` (raw text),
`bodyBase64`, `multipart` (`{ "fields": {...}, "files": { "file": { "name", "type", "content" | "base64" } } }`),
or `bodyFrom` (raw bytes captured earlier with `"captureBody": "var"`, e.g. export → import).
`capture` takes dotted paths into the JSON response; variables are per server
(Node's id goes to Node, Rust's to Rust) and interpolate as `{{var}}`.
The normaliser (`parity/normalise.mjs`, owned by Wave 0) only maps nanoid-shaped
strings not present in the seed DB to `<id:N>` in first-seen order, masks ISO
timestamps from the current run as `<now>`, ignores key order and drops
`details` on 400s. Ids embedded inside longer strings (e.g. `<id>.pdf`) are not
masked; binary bodies are compared byte for byte. If you need more, stop and
ask rather than editing the harness.

**Compatibility checks:** `cargo test -p openfinance-core --test compat` (in the
gates) and `crates/openfinance-core/tests/compat/roundtrip.sh` (needs Node).

- `routes/reset.ts` → `http/routes/reset.rs`

Endpoints:
- `GET /api/documents` (filters `investment_id`, `account_id`, `life_insurance_id`)
- `POST /api/documents` (multipart)
- `GET /api/documents/:docId`
- `DELETE /api/documents/:docId`
- `GET /api/backup/export`
- `POST /api/backup/import`
- `POST /api/reset`
- `POST /api/reset/transactions`

**What is reproduced:**
- **Multipart upload.** Hono `parseBody` plus undici's multipart parser and MIME
  parser (`documents/form.rs`), so the same bodies are accepted or rejected.
- **Upload storage.** Files are stored as `uploads/documents/doc_<nanoid12><ext>`,
  OFE1-encrypted, so either server can read the other's uploads.
- **Export.**
  - It writes the exact bytes of `JSON.stringify(backup, null, 2)`, using JS
    number formatting.
  - Documents are listed in `readdirSync` order (bytewise).
  - ZIP entries are in adm-zip's sorted order: lowercase names compared with
    `localeCompare`, done with ICU4X root collation.
  - The archive is FWB1-encrypted with the stored `backup_key`, or on desktop
    with a key derived from the passcode.
- **Import.**
  - Decrypts FWB1 the same way Node does: stored key first, then the header
    password with the candidate usernames.
  - Parses JSON with correctly rounded numbers (`backup/jsonparse.rs`, because
    serde_json's default float parsing is not correctly rounded).
  - Runs Node's whole migration pipeline, including JS `Date` and `+`
    semantics.
  - Inserts the way drizzle does (defaults, boolean mapping, 1000-row chunks)
    and binds values the way better-sqlite3 does (numbers as doubles, array
    spreading, placeholder-count errors).

**Reuse for Wave 2 investments (`/api/investments/:id/documents`):**
- `documents::{upload(state, headers, body, UploadParent::Investment(id)), download, remove}`
- `services::document::{list_documents, DocumentFilters, read_document, delete_document}`

**Runner feature added (`parity/run.mjs`).** A step can set
`"decode": "backup"`. A binary response body is then FWB1-decrypted with the
harness key (`deriveBackupKey(DB_KEY, "desktop")`) and unzipped with adm-zip.
It is compared as:
- `{ encrypted, entries: [{ name, isDirectory, json, isStringifyOutput } | { name, isDirectory, base64 }] }`
- If decoding fails, as `{ encrypted, decodeError }`.

Only the random IV and the ZIP container metadata (timestamps, compressed
bytes) are dropped. Entry order, names, the parsed `backup-data.json` (through
the existing normaliser, so `exported_at` is `<now>`), the check that its text
is exactly `JSON.stringify(json, null, 2)`, and every document byte are all
compared. No masking or normalisation rule was added. `"captureZip": "var"`
captures the decrypted ZIP so that `bodyFrom` can re-import it. This is needed
because the harness passcode is not a ByteString, so an encrypted backup can't
be re-imported via `x-backup-password` (QUIRKS Wave 1 data #4).

**Not compared by parity:**
- **A successful `POST /api/documents`.** The response and later lists contain
  `file_name: doc_<nanoid12>.<ext>`, which the normaliser does not mask (the id
  is inside a longer string). Instead:
  - `tests/compat_backup.rs` uploads through the Rust route and checks the
    name shape and OFE1 bytes.
  - Node then imports Rust's export and serves the same bytes.
  - Parity covers list, download, delete and every upload rejection, using
    documents restored from a backup ZIP with fixed names.
- **Known edges that are not replicated:**
  - V8's legacy date parser beyond the numeric `YYYY/M/D` and `M/D/YYYY` forms
    (other forms give Invalid Date in Rust).
  - JSON numbers outside the double range become `null`, not ±Infinity.
  - JSON nesting deeper than 5000.
  - Malformed ZIPs the `zip` crate and adm-zip disagree on (both reject what
    the scenarios send).

**Compatibility tests.** `cargo test -p openfinance-core --test compat_backup`
covers both directions:
- **Node → Rust.** Encrypted and plain fixtures produced by the real Node
  route; regenerate them with `tests/compat/regen-backup-fixtures.sh`.
- **Rust → Node.** Encrypted and plain exports from Rust are imported by the
  real Node route through tsx. This needs `apps/server/node_modules`. Set
  `OPENFINANCE_SKIP_NODE_COMPAT=1` to skip it explicitly.
- **Equality check.** Each direction compares the decoded re-export (every row
  and every document byte).
